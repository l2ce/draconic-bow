# Важные детали разработки

Проверки и визуальную приёмку выполняет пользователь. Агент не запускает проверочные команды, сборку и браузерные сценарии без отдельного запроса; dev-сервером также управляет пользователь.

## Структура

- `src/App.tsx` — состояние сцены, загрузка, анимации и интерфейс.
- `src/components/EnchantControls.tsx` — контроллер компактной кнопки заточки.
- `src/components/EnchantDebugDialog.tsx` — скрытое окно прямого выбора уровня по Ctrl+Alt+M.
- `src/hooks/useEnchantAttempt.ts` — единый таймер попытки, прогресс, блокировка повторных нажатий, результат и секундная пауза обратной связи.
- `src/components/EnchantButton.tsx` — интерактивная кнопка: целевой уровень/шанс, заливка прогресса без видимых процентов, успех/неудача, максимум, загрузка и повторная загрузка при ошибке.
- `src/lib/enchantAttempt.ts` — пользовательская шкала шансов; это не вероятность всей цепочки и не данные игрового сервера.
- `src/viewer/ViewerEngine.ts` — Three.js, камера, микшер анимаций и жизненный цикл.
- `src/viewer/WeaponEnchant.ts` — аура, stencil-маска и частицы.
- `src/lib/bowMaterial.ts` — восстановление native-флагов материала лука.
- `src/lib/publicAsset.ts` — пути ресурсов с учётом `import.meta.env.BASE_URL`; новые файлы из `public/` загружать через этот helper.

По согласованию с пользователем старая панель удалена. Осталась компактная кнопка «Заточить на +N» с шансом успеха и заливкой процесса. Повторные попытки и сброс во время заточки/секундного показа результата заблокированы. После достижения +16 та же кнопка позволяет начать заново с +0; отдельного ручного сброса на промежуточных уровнях нет.

Размер кнопки не зависит от статуса: ширина и высота заданы явно, на мобильном ширина ограничена экраном и сохранено центрирование. Текст может переноситься без обрезания и изменения габаритов кнопки; многоточие в строке процесса — часть текста, не CSS-усечение. На десктопе кнопка заточки и панель камеры выровнены центрами по общей горизонтали; на мобильном кнопка остаётся над управлением анимациями.

С 768px панель камеры отображается сбоку напротив кнопки заточки. На планшете и десктопе размер кнопки одинаковый — 256×64px: сохранены прежние иконка, левое выравнивание и шрифт, уменьшен только лишний запас ширины справа. Ниже 768px панель камеры скрыта, кнопка заточки расположена внизу по центру и сохраняет свою симметричную мобильную компоновку; управление камерой касаниями и жестами сохраняется.

## Публикация

Workflow `.github/workflows/pages.yml` публикует `dist/` при пуше в `main` или ручном запуске через Actions. В настройках репозитория необходимо заранее выбрать **Pages → Source → GitHub Actions**, иначе `Configure Pages` завершается с 404 ещё до сборки. Базовый путь берётся из метаданных Pages; локальная разработка остаётся на `/`. Отдельная ветка `gh-pages` и пользовательские секреты не нужны.

## Не потерять при изменениях рендера

1. Raw GLB содержит `alphaMode=BLEND`. После загрузки `bowMaterial.ts` восстанавливает сочетание alpha blending, `depthWrite=true`, `depthTest=true`, `alphaTest=160/255`, `DoubleSide`, `forceSinglePass=true`. Без этого детали лука просвечивают при поворотах. Не заменять комбинацию просто на `transparent=false`.
2. Кубическая карта обычной ауры загружается как sRGB. Палитра ауры переводится из sRGB в linear отдельно; на выходе выполняется одно преобразование. Не менять вместе с этим уже согласованные цвета/тинт частиц.
3. Alpha-aware stencil-маска исключает широкий ореол на пикселях лука. Вместо сплошной окраски обычная сцена использует `enchant-weapon-shimmer`: перелив по светлым деталям исходной текстуры, ограниченный областью ауры; тёмные углубления не подсвечиваются. Порядок: лук → маска (1) → аура (2) → подсветка деталей (3) → частицы (5). Старый сплошной слой `enchant-surface` доступен в диагностике. Stencil и подсветка деталей — веб-реконструкция, не доказанный исходный проход игры.
4. `volume` / `volume-full` остаются dev-экспериментами. Форма и сила ауры ещё не прошли окончательного согласования; не включать эксперимент автоматически и не менять GLB ради цвета свечения.
5. Лимит FPS не добавлялся. Частота ключей 30 Гц и `delta <= 0.1` не ограничивают рендер до 30/10 FPS. Измерения headless SwiftShader не отражают FPS браузера пользователя.

## Dev-диагностика

**Ctrl+Alt+M** открывает скрытое окно заточки в обычной сцене и в диагностике, в том числе в production. Вводится целый уровень **0…16**; «Применить» или Enter задаёт его мгновенно и отменяет незавершённую попытку/показ результата, даже если выбран прежний уровень. При открытии подставляется текущий уровень. Escape, «Отмена», щелчок по фону или повторное сочетание закрывают окно. Горячая клавиша привязана к физической клавише M и работает также с русской раскладкой. Для применения должны загрузиться модель и эффект.

Текущая настройка яркости по игровым референсам: `AURA_GAIN = 2.4`, `WEAPON_SHIMMER_GAIN = 0.6` в `WeaponEnchant.ts`. Усиление ореола 2.4 задано пользователем после сравнения вариантов. Это коэффициенты веб-рендера для визуальной калибровки, не извлечённые параметры клиента. Цвета/порог +4, частицы с +7 и их плотность по уровням берутся из исходного `enchant.json`; масштаб Rangesample сохранён. Результат этой итерации ещё ожидает визуальной оценки пользователя на +4, +8–9 и +14–15.

Следующие URL-параметры действуют только в режиме разработки; production их игнорирует:

- `?motionStats=1` — FPS рендера/обновления скелета, p95 и GPU.
- `?enchantStudy=base` / `bow-blend` — исправленный/старый базовый материал лука.
- `?enchantStudy=aura|particles|surface|mask` — отдельные слои.
- `?enchantStudy=before|full` — прежняя/текущая композиция; `aura` показывает усиленный ореол отдельно, `aura-srgb` — ореол с прежней яркостью.
- `?enchantStudy=aura-data|volume|volume-full` — изолированные эксперименты.
- `&studyView=front|back|side|quarter` — ракурс.

В `enchantStudy` поза фиксируется на 0,5 с клипа, цвет/частицы заморожены. Для измерения движения использовать обычный URL. Старые сценарии снимков и helper `setLevel` рассчитаны на удалённую панель и мгновенное повышение: требуют адаптации к новой кнопке и случайным трёхсекундным попыткам. Не считать исторические отчёты приёмкой текущего интерфейса.

Исследование городских ресурсов завершилось без подключения города: пользователь оставил графитовое окружение. Инспектор ресурсов сохранён в `tools/inspect_environment.py`, его данные и прочие генерируемые отчёты остаются в `../asset-work/`, а не в репозитории.
